# 根 Session 使用独立进程，子代理生命周期归插件所有

Pace 为每个实际启动的根 Session 分配独立进程，运行应用打包的 Pi SDK 与用户插件。这样 `process.cwd()`、模块缓存和插件全局变量都属于该根会话；不同项目不必依赖每个插件专门实现根作用域隔离。同一项目的不同根会话也分别隔离。代价是每个已启动会话有独立的进程内存与启动开销。

子代理由创建它的插件负责创建、保留复用、取消和释放，主 Agent 通过插件工具管理工作。Pace 不获取每个子 Session，不维护专用子代理树、控制协议或 Dock 面板。兼容目标是原版 Pi 插件能在正确的运行环境里工作；当前已验证 Tintinweb 0.19.0，不把此验证扩大为所有插件的完整 GUI 兼容保证。将来 Pi 原生支持子代理时，这一内部职责可以交给 Pi，不需要撤销根会话进程隔离。

## 承载与退出

公共 Electron 后端继续拥有 Gateway、事件序号、Journal 和查询；`SessionProcessDriver` 通过 Node IPC 转发已有驱动操作，每个 `session-worker` 只接受一次根会话初始化。SDK Normalizer 在会话进程内订阅主 Session，将普通数据事件发回后端。插件内部对象不跨进程传递。恢复和分支使用 Pi 日志保存的 cwd，在加载扩展前设置；活跃 Session 重连复用原进程，不重新加载插件。

正常 Stop 使用 Pi 的 abort，作用于当前运行；它不等于插件的全部后台工作结束。切换视图、父 Active Run 结束、归档投影不会回收会话进程。删除根 Session 和退出应用会触发 Pi `session_shutdown`，由插件清理子会话，然后释放 SDK、退出进程并刷写收到的事件。会话进程超过 25 秒未退出时强制终止，并记录中断；应用总退出上限仍为 30 秒。

Unix 上每个根进程有自己的进程组，宿主回收普通后代；插件刻意启动的独立守护进程仍由插件的退出逻辑负责。公共后端异常退出时，会话进程通过 IPC 断开感知失去宿主并开始有上限的清理。单个根进程异常退出只让该 Session 失败，其他根继续运行；下次明确执行操作才恢复，不自动重放未完成的任务。

## 原有适配的处理

移除 `subagents:host:ready`、专用观察器和逐子代理控制接口，移除对应 Dock 展示与活动数量。保留主会话工具调用/结果、通用扩展退出、创建/释放竞态保护和历史记录。Session 总用量直接使用 Pi 的统计，保留插件通过工具结果上报的用量，不再为全树相加而扣除子费用。

独立 Trajectory 页面继续读取扫描目录中的 Pi JSONL；没有持久化的子会话不承诺回放。已有文件不删除，旧隐藏观测事件仍不混入主对话。用户插件设置不自动迁移，安装说明改为上游原版。

历史读取与执行初始化按 [ADR-0021](0021-session-fork-resume-persistence-layering.md) 分离：查看冷历史不分配根进程，首次执行才分配；查看存活会话复用原进程。本决策不实现自动空闲回收，也不把父 Agent 停止输出当作插件后台任务已结束。
