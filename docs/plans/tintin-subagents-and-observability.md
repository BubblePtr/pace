# Tintinweb 子代理集成与观测规划

- 日期：2026-09-13
- 状态：用户已批准，A–D 已实现；交付结果与版本边界见[子代理运行与观测](../subagent-observation.md)。
- 目标：简化 Pace 的打包入口，采用 Tintinweb 的进程内子代理执行模式，让主会话能够管理、观察和回放其子会话。
- 验证基线：Pi SDK 0.84.3；原版 `@tintinweb/pi-subagents` 0.19.0，commit `e955e29c51b7a6cce37e1108cd2d6c57a77e151c`。

## 1. 已知事实

以下为制定方案时的事实和缺口；已完成的实现与验证不覆盖此历史基线。

1. #294 已合并：为旧 `pi-subagents` 的独立 runner 提供真实 SDK/peer 入口与 manifest，把 Pace 后端入口放进 Pi 包目录，并发现系统 Node。
2. #300 仍为 OPEN、未合并：为上述独立 SDK 入口补 OAuth 初始化。后续实施应取消这条独立入口方案，保留主后端必需的 OAuth 初始化。
3. 原版 Tintinweb 插件已经在当前打包产物中通过隔离试跑：父子同进程；子任务未结束时父会话继续；子代理执行真实 read 并通知完成；插件 stop RPC 能取消请求。PATH 为空且 Node 路径不存在时仍可运行。两条本地模拟认证链路得到 `2 passed (6.5s)`。
4. 实测缺口：Pace 停止父会话、删除会话均不取消后台子代理；退出应用时没有观察到 `session_shutdown`；插件用 `process.cwd()` 读取项目代理，无法加载会话项目下的定义。
5. 子会话内部 SDK 事件存在，但 Pace 当前只订阅主会话。插件的主要公共生命周期事件过滤嵌套及 Workflow 所属代理，不能直接提供完整子会话树。

试跑报告与原始事件保存在 `/tmp/pace-tintin-trial-results/`。该证据基于本地模拟模型，不能当作真实服务登录、刷新令牌或所有插件功能的验收。

## 2. 设计原则与生命周期

- Pi 与插件继续拥有会话内容、代理创建、工具配置和调度。Pace 通过公开的宿主观测/控制接口接入现有子会话。
- 观察已有子会话时不再次调用 `createAgentSession()` 或 `bindExtensions()`，避免生成第二个会话或重复执行扩展生命周期。
- 子代理对象、Pi 子会话、一次执行轮次分开标识。同一代理可以恢复并执行多轮；不能把三者合并为一个 ID。
- 父子所属关系使用明确元数据，不能从文件路径、工具名或 Pi 的 fork `parentSession` 字段推断。
- 进程退出能力不是本期目标；退出 Pace 时后台子任务应收束，历史可在重启后查看。

| 用户操作或事件 | 目标行为 |
| --- | --- |
| 父会话当前轮次完成 | 子代理继续；主会话仍可接收输入 |
| 切换会话、收起 Dock | 子代理继续 |
| 主会话空闲但存在运行/排队的子代理 | 展示子代理活动，仍提供停止入口；不能仅凭父 `agent_end` 宣告整项工作结束 |
| 停止某个子代理 | 取消该代理及其后代，等待执行收束，其他代理继续 |
| 主会话“停止” | 取消父运行和所属子代理树；停止期间拒绝新派生任务，已排队任务不能继续启动 |
| 删除主会话 | 先停止、收束、释放运行态，再按既有删除语义移除投影 |
| 归档主会话 | 存在任何活动子代理时按现有活动会话限制处理 |
| 退出 Pace 或重启后端 | 执行会话 shutdown 和资源清理；正常退出有时间上限，超时明确记录未完成清理 |
| 后端异常退出、应用重新启动 | 保留已记录轨迹，把未完成执行标为中断，不伪装成功或自动恢复运行 |

“收到取消请求”与“已经停止”是两个状态。不得先把记录改成 stopped，再仅根据状态过滤的等待函数判断已全部结束。

同进程工具若不响应取消，需在超时后明确显示停止未完成；不能为停止一个子代理而杀掉承载其他会话的共享后端，也不能把超时伪装成已停止。

## 3. 阶段一：回退旧 runner 的打包兼容逻辑

### 改动

- 恢复普通 Pace 后端入口，取消把入口放入 `@earendil-works/pi-coding-agent` 包目录的安排。
- 删除用于独立消费者的 SDK/peer 多入口、生成 manifest、相应 `extraResources` 和 asar 外分发规则。
- 删除为该兼容方案新增的系统 Node 自动发现、后端 PATH 注入、Extension Node.js 预检及对应文档承诺。
- 保留 Pi 的进程内扩展加载机制，继续使用固定 SDK。
- 通过 Pi 的公开 `bun-oauth` 注册接口保证主后端 OAuth 可用；主题、WASM、node-pty 等资源根据恢复后的布局放置。
- node-pty 的解析必须按最终位置验证，不能机械地反向应用 #294 的全部 diff。
- #300 的独立入口增强不再合并；实施时关闭并说明替代方案。历史发布日志保留，新增本次兼容范围调整说明。

### 验收

- 普通主会话、原版 Tintinweb 进程内前台/后台代理在新打包布局中均可运行。
- API Key 与 Codex OAuth 本地模拟路径通过；主会话模型、主题与图像/WASM 功能无回归。
- 清空 PATH、不提供全局 Pi/Node，仍能完成上述代理任务。
- 打包版终端实际执行命令、后端重启正常。
- 删除只保护旧入口文件形状的测试，保留并调整实际运行行为测试。

### 影响范围

`apps/desktop/build/pi-runtime-bundle.ts`、`electron.vite.config.ts`、`electron/{main,backend}.ts`、`electron-builder.yml`、`packages/backend/src/drivers/system-node*`、环境预检、主后端 OAuth 初始化、产物测试与发布文档。

兼容变化需明确：旧 nicobailon 插件的独立后台 runner 不再由 Pace 提供这套自动兼容。已有会话历史保留；本阶段不自动卸载用户插件。

## 4. 阶段二：正式适配 Tintinweb

### 插件侧

1. **按会话隔离配置。** 将代理定义、settings 和相关配置缓存按 `ctx.cwd` / 根会话作用域读取。审计模块级注册表，覆盖两个项目并行运行及相同代理名；不用 `process.chdir()` 修复。
2. **提供明确的观测接口。** 支持获取当前代理快照、订阅变化、在子会话开始 prompt 前取得其事件源。覆盖排队、启动失败、嵌套、Workflow 所属代理和恢复执行；数据包括根会话、父代理、代理 ID、Pi 会话 ID、触发工具调用关联及可用的文件路径。
3. **提供可等待的控制。** 停止单棵代理树和关闭根会话时，等待真实执行 Promise 与初始化过程收束；停止新任务入队，处理创建途中取消、重复取消和晚到完成通知。
4. **保持原有插件语义。** 保留模型继承、工具/扩展隔离、嵌套深度、配置与资源加载。观测入口由管理器发布，不能依赖每个子会话都加载一个普通观察扩展，否则 `isolated` 等配置会造成漏记。

接口在插件支持层正式声明并版本化；不通过全局首个 manager、运行时替换 SDK 导出或探测安装目录来对接。接口只覆盖本次已确认需要的快照、观测、停止/关闭能力，不建立额外的通用执行框架。

适配以固定上游基线开发，经用户授权通过 [BubblePtr/pi-subagents PR #1](https://github.com/BubblePtr/pi-subagents/pull/1) 交付，固定 commit `6e8b946804e6be520b71f5e15f88034618b1060f`。启用方式见[子代理运行与观测](../subagent-observation.md)。上游贡献与 npm 发布保留为后续动作；直接使用上游 0.19.0 不能提供本期新增的宿主协议。

### Pace 侧

- 建立按根会话隔离的薄适配器，接收插件观测事件和控制能力。
- 接入停止、删除、后端退出路径；明确 shutdown 只执行一次，避免只调 `session.dispose()` 却漏掉扩展关闭事件。
- 每个子会话保留插件提供的模型、工具和资源状态；Pace 不再运行一套子代理调度器。
- 迁移在新会话生效。试用配置只启用明确版本的 Tintinweb；旧会话和用户其他扩展不自动改写。

### 验收

- 两个项目的同名自定义代理各自生效，控制命令和事件不会串会话。
- 父轮次结束不取消子代理；停止主任务、停止子树、删除会话和正常退出按上表收束。
- 创建中、排队中、工具执行中、完成与取消同时发生时，结果一致且不会出现“已停止后又开始写文件”。
- 原有普通 CLI 用法及前台等待、后台返回语义保留。
- SDK 子会话只创建一次、扩展生命周期只绑定一次。

## 5. 阶段三：子会话观测窗口

本阶段先交付数据链路，再交付界面。

### 3A：状态、轨迹和历史

- 在执行首个 prompt 前接入 SDK 事件，每个子会话独立使用现有 Normalizer，再进入 Runtime Gateway、Journal 和 Projection。
- 保存父子所属关系与触发工具调用关联；主会话的 `Agent` 步骤可定位到对应子会话，嵌套可沿树查看。
- 快照与增量订阅共同支持重连：订阅切换期间不能漏首条事件或重复记账。保留事件序号、模型实际输出、工具参数/结果及真实生命周期时序。
- 历史按现有 Journal 的边界事件与最终内容快照回放；无需保存每个 token 的 delta 来重建完整文本，但不能丢失工具起止、错误和中断状态。
- Pi session JSONL 继续作为模型上下文真相，Pace Journal 作为展示和时序真相。明确持久化策略，不依赖临时 `.output` 文件长期存在。
- 保存实际模型与 thinking 档、Token/费用及来源。用量以子会话实际模型调用为归属，父聚合字段不得再次叠加；覆盖插件 `reportUsage` 开/关两种情况。
- 用于执行树停止和历史回放的元数据由后端维护，Renderer 不推断代理是否仍运行。

主要模块：`packages/core/src/{runtime-gateway,agent-runtime-event}.ts`，后端 `drivers/`、`gateway/`、`persistence/`，前端 `entities/runtime/`、`entities/session/`。

### 3B：Dock 中的子会话面板

第一版形态：主会话右侧 Dock 增加子会话入口。

- 列表/树展示代理名称、任务描述、排队/运行/停止中/完成/失败状态、当前工具、耗时和用量；实际模型与 thinking 档可在详情查看。
- 点击代理查看其实时对话与 Trajectory；工具步骤复用现有参数、结果、错误、时序展示。模型只展示 provider 实际返回的内容。
- 父会话中的 `Agent` 工具步骤提供定位入口，子详情可返回父代理。
- 主会话空闲且子代理运行时保持活动提示与停止入口；关闭面板只改变视图。
- 完成后与重启后仍能查看历史；执行中断、没有历史、部分记录缺失均有明确状态。
- 控制按能力展示，首版提供停止；已有 steer 能力通过正式接口接通后提供定向消息入口。
- Workflow 所属代理纳入观测树，工作流 DAG 编辑器、独立操作系统窗口和通用 Extension UI 框架不在本期。

UI 实施遵循 Astryx 发现流程；新增共享组件须注册到 `/design`，更新对应设计文档和 UI intent 绑定。复用 Trajectory 展示逻辑，避免另做一套工具时间线解析器。

### 验收

- 一个父代理并发启动两个子代理，窗口可分别查看实时工具调用；一个结束后另一个仍运行，状态独立。
- 打开面板时任务已经运行，快照与后续事件可正确拼接；反复切换会话或刷新不丢失、不串流。
- 嵌套和 Workflow 所属代理可定位，停止子树不会误停兄弟代理。
- 查看历史时工具参数、结果、耗时、实际模型和用量与运行记录一致；父子成本无重复。
- 正常退出与异常退出后都能查看已有记录，异常结束不会显示为成功。
- 以打包版 Electron 和可控本地模型完成端到端验证，并提供实际 UI 截图。

## 6. 交付顺序与测试安排

| 切片 | 交付结果 | 依赖 |
| --- | --- | --- |
| A：打包恢复 | 简单后端入口，Tintinweb 在该布局通过运行验收 | 无 |
| B：插件/宿主适配 | 配置隔离、正式观测接口、可等待的生命周期控制 | A 的打包基线 |
| C：子会话数据链路 | 可查询状态、完整事件接入、持久化与用量归属 | B 的接口 |
| D：观测面板 | 实时树与详情、父子导航、停止和历史回放 | C |

B 涉及上游插件与 Pace 两侧，实际 PR 可按仓库拆分。Pace 内有依赖的 PR 使用项目规定的 `gh stack`，不手工将普通 PR base 串成链。

测试优先保护已复现行为：把试跑中“停止后仍完成”“项目代理找不到”等观察改成目标行为的失败回归测试，再实现；并发测试使用可控请求/工具闸门，不以固定 sleep 判断正确性。界面使用状态/交互测试和截图；不为入口路径字符串或文件列表增加镜像断言。

完整测试、类型检查、打包验收按变更范围分阶段执行；实装试用前统一验证新布局 + 适配版插件 + 观测 UI 的组合。真实账号认证与发布签名不由本地模拟测试替代。
